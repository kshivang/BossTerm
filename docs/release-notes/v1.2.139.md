# Release Notes - v1.2.139

**Release Date:** 2026-07-26

## Highlights
Boss Calling: you can now voice-call the session's AI agent — from the app itself via a "Call BossTerm" pill in the status strip, or remotely from the share viewer's bottom bar. The agent can inspect and act on the session through the same tool surface BossTerm already exposes over MCP.

## New Features
- Boss Calling from the share viewer: a remote viewer with control of the share can talk to the session's AI agent. Audio goes browser↔OpenAI over WebRTC and never through the tunnel; the host mints a short-lived ephemeral client secret from its own key, and the agent's function calls ride the existing share WebSocket (#345)
- Boss Calling in-app: "Call BossTerm" in the host window's status strip opens a call with no browser and no WebRTC — the host speaks the Realtime API over the JDK's own WebSocket, with `javax.sound.sampled` handling PCM16 24 kHz capture and playback (#345)
- Call bar on both surfaces: a real audio level meter (mic while you talk, the agent's own track while it answers), what the agent is doing right now, Mute, and End call (#345)
- The in-app agent gets the whole MCP surface — every tool registered on `BossTermMcpServer`, with descriptions and schemas taken from the server so the two can't drift. Shares keep the narrower curated catalog (#345)
- New `close_panel` MCP tool: close a pane or a whole tab by id (#345)
- Key management: the OpenAI key lives in a chmod-600 `~/.bossterm/voice.json`, deliberately outside `settings.json`. Clicking Call with no key opens a dialog to add one and places the call on save (#345)
- New "Boss Calling (voice)" settings section, shown both in Settings and in the Share windows so the key can be added where the link is handed out: separate switches for the in-app and remote call surfaces, microphone sensitivity, "Give the agent every MCP tool", and a status-indicator toggle (#345)
- In-app calls follow the focused pane rather than a fixed anchor tab, and embedders can shape the agent's instructions and available tools (#345)
- Host-side notification whenever a remote call starts or ends — a call is remote hands on the machine, so it announces itself through the same channel as a share approval request (#345)

## Bug Fixes
- A burst of control frames on a share connection could evict queued replies: `BoundedViewerOutbox` now has a bounded control lane that is never evicted and drains first, yielding to terminal output so control traffic can't starve the screen (#345)
- Tool results are clamped in one place for both call surfaces, so an oversized read can no longer overflow the host's outbox and drop the viewer, or throw viewer-side after the agent had already narrated the result (#345)
- macOS packaging now declares `NSMicrophoneUsageDescription` and the audio-input entitlement; without them a packaged app is denied the microphone (#345)

## Improvements
- Share-scope enforcement precedes every voice tool dispatch, so a viewer on a session-scoped share cannot reach a tab the share doesn't cover; tool arguments are filtered to the advertised schema, and a tool the model names out of scope is refused while a merely stale focus falls back to the in-scope anchor (#345)
- Call tokens are bound to the connection they were issued to, retired on hangup, disconnect, revocation, or when the share stops, and capped at one live call per connection — no handle outlives its call (#345)
- Ephemeral-secret minting is rate-limited and budgeted process-wide, with the call slot reserved before minting and refunded on failure, so a redial storm can't run up a bill against the host's key (#345)
- The master switches act as kill switches: turning Boss Calling off ends calls already in progress on both surfaces instead of only hiding the button (#345)
- Audio path hardening: serialized WebSocket sends behind a single-consumer queue (concurrent sends were silently dropping mic frames), dedicated capture and playback threads rather than a shared dispatcher, bounded play queue, barge-in that survives a backed-up speaker, and a lost microphone that reports itself instead of failing quietly (#345)
- Exactly one follow-up turn per tool round on both surfaces, with per-call timeouts that feed an error back rather than pinning the call at "Working…" (#345)
- Cross-language contract tests plus a fake-browser viewer harness and fake socket/audio drivers cover both call surfaces, including the scope-escape, token, kill-switch, and rate-limit regressions (#345)
