# Release Notes - v1.2.140

**Release Date:** 2026-07-26

## Highlights
A shutdown-correctness release for session sharing: `SessionShareManager.shutdown()` now cancels its own in-flight work, so a pre-warm parked mid-flight can no longer wake up afterwards and bind a fresh share server behind a manager that has already torn everything down.

## Bug Fixes
- Session sharing could re-bind its server after shutdown. `shutdown()` cancelled only its settings watcher, never its own scope — and the pre-warm it launches parks for up to 5 seconds waiting for the BossTerm MCP server to claim its port. A shutdown during that wait returned, then the pre-warm woke and bound a new Ktor server; embedded in a plugin whose classloader was closing, that late bind ran against dead classes. `shutdown()` now latches, supersedes any in-flight remote op, and cancels its own work *before* the teardown proper, since the engine stop is the widest part of shutdown and cancelling after it would leave the exact window open (#346)
- A shutdown latch backs up the cancellation, because cancellation alone cannot finish the job: `ensureEngineLocked()` has no suspension point, so a pre-warm already inside it runs to completion regardless. The latch is checked in the binder and re-checked after it adopts the engine, which is what makes "shut down" mean "no server may be bound"; `start()` clears it so the singleton re-arms for an embedder that loads BossTerm again (#346)
- `stopEngineLocked()`'s engine stop is now `NonCancellable`. Being cancelled between "decided to stop the engine" and "stopped it" would run the `finally` block, clearing `engine` while the server was still bound, leaving `shutdown()` nothing to stop. Bounded by the same 300ms/1000ms stop budget (#346)
- Deliberate cancellation is rethrown instead of being logged as "Error stopping session-sharing server" (#346)
- `stopEngineLocked` passes the captured port to `teardownRemoteAccess`, not just to the log line — the field can be nulled underneath it (#346)
- `stopEngineLocked` and `stopAll()` return early once the shutdown latch is set, the guard `unshare()` already had. Now that the path is `NonCancellable` end to end, a teardown already inside the fence would otherwise spawn a `tailscale` child process and stop the engine after `shutdown()` returned, inside the classloader being unloaded — and redundantly, since `shutdown()` does both itself, inline (#346)
- `requestEmbeddedFit` refuses once the shutdown latch is set; it could otherwise repopulate `fitActiveTabs` after `shutdownLocked` had drained it, registering a fit nothing will ever undo against an embedder already let go of (#346)

## Improvements
- The settings watcher's pre-warm and cloudflared prefetch are now its children rather than coroutines on the manager scope, which re-resolves `lifecycle` on each access — a shutdown/re-arm landing between the watcher's guard and its launch could attach the new coroutine to the fresh lifecycle and outlive the cancel. As a child, it is bound at creation and dies with the watcher (#346)
- The watcher's collect body runs in a `supervisorScope`, so a throw from the pre-warm or the prefetch can't cancel the watcher and take the settings observer down with it — permanently and silently, since the grandparent is itself a supervisor and `bossterm-app` calls `start()` exactly once (#346)
- `engine` is `@Volatile`: `shutdown()` is synchronous and so cannot take the mutex the binder holds when it writes the field (#346)
- New `SessionShareShutdownTest` drives the real path — settings watcher, parked pre-warm, real port binds — against a throwaway `SettingsManager` and a reserved run of ten consecutive free ports, with a remote mode that arms the pre-warm without shelling out to `tailscale` or `cloudflared` (#346)
