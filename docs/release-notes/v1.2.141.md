# Release Notes - v1.2.141

**Release Date:** 2026-07-27

## Highlights
Boss Calling opens up to the embedder: an app hosting BossTerm can now hand the in-app voice agent its own tools, merged into the built-in terminal surface behind two safety tiers, and can name the call button whatever its own users would recognise. Alongside that, `BossTermMcpManager.stop()` finishes synchronously, so an embedder unloading BossTerm can no longer close the classloader out from under a teardown still in flight.

## New Features
- `TabbedTerminal` gains `voiceToolSource`, letting an embedder expose its own tools to the in-app voice agent. BossTerm ships thirteen tools, all about terminals, because that is all BossTerm has; an embedder generally has more - BossConsole's terminal-tab plugin hosts a `boss` MCP server with 106 tools covering git, the browser, plugins, secrets and RPA, and those are the tools the person talking to Boss actually wants. `tools()` is re-read on every enumeration - at session config and before each tool call - because hot reload is a normal event and a list captured at call start goes stale inside the call (#349)
- Two safety tiers guard the merged surface, additive only: an embedder rule can widen what BossTerm catches and can never narrow it, and a rule that throws counts as a match. Tier 1 is hard exclusion - a `sensitive` tool is never advertised and is refused by name if the model produces it anyway, because a voice call sends everything it touches through a third-party realtime API and then says something about it out loud. Tier 2 is confirmation: the first call to an `irreversible` tool does not run, it returns a single-use token keyed to the exact arguments that the agent must redeem *after* the user has spoken. An embedder with a UI installs `approve` instead (#349)
- `TabbedTerminal` gains `callLabel: String?` - "Boss Calling" is the feature and stays fixed, but the button's text belongs to the embedder, since BossConsole's users have never heard of BossTerm. Null keeps the standalone "Call BossTerm"; the label is resolved once and threaded to every surface that renders it - the status-strip segment in all six states, the key prompt that segment opens, and the Boss Calling settings panel in both share windows (#347)

## Bug Fixes
- `BossTermMcpManager.stop()` fired its engine teardown onto `parentScope` and returned immediately. An embedder unloading BossTerm closed this instance's classloader while that coroutine was still queued, and it died on its next first-time class load, followed by LinkageErrors from Ktor classes resolving across two loaders. `stop()` now latches, bumps the lifecycle epoch and cancels *before* the teardown proper, then runs the teardown on a dedicated daemon thread and waits 1.5s for it. `bossterm-app` had the same bug in a milder form - its shutdown hook called `stop()` and then cancelled `mcpScope` on the very next line (#348)
- Cancellation alone could not finish that job: `reconcile()` reaches `startEngineLocked()` through `mutex.withLock`, whose uncontended fast path returns without checking cancellation, and `startEngineLocked()` has no suspension point at all - so a cancelled collector could still arrive holding a live intent to bind. The latch, checked there, is what makes "stopped" mean "no engine may be bound" (#348)
- The confirmation gate livelocked when the agent acknowledged its own call. Check (4) compared the user's turn against the *latest* agent turn, so the model's own preamble - arriving in the very response that redeems, since `response.output_audio.done` can precede `response.function_call_arguments.done` - moved the goalposts past the answer it was acknowledging. Told to wait for the user, the model asks again, the user answers again, and it acknowledges again. The gate now freezes the agent turn as of the user's answer and compares that against the mint; both existing negative tests still fail closed (#349)
- An illegal OpenAI function name does not fail as one broken tool - the whole `session.update` is rejected, every tool disappears and the call dies. The external half is sanitised at the merge, but the base half could produce one today: `BossTermMcpConfig.toolNamePrefix` is embedder input concatenated straight onto every built-in name with nothing validating it, so a prefix containing a space names all thirteen illegally. The assembled array is now filtered, costing the offending tools and a log line instead of the call (#349)
- `DropExternal` never dropped anything - nothing read the enum outside the `PrefixExternal` branch, so a colliding tool fell through to the suffix loop and was advertised as `run_command_2`, contradicting `disambiguate`'s own documented invariant (#349)

## Improvements
- Collisions between the two tool sets are the normal case, not an edge one: 13 of the 106 `boss` tools are BossTerm's own, re-exported by terminal-tab. The default drops the external duplicate, since BossTerm's is the implementation with the scope and focused-pane logic in front of it, and prefixing is available for an embedder whose same-named tools genuinely differ. Names are made legal for OpenAI's grammar with the mapping kept, so a result routes back to the source's own name (#349)
- Payload volume is bounded rather than assumed. Measured on the live surface rendered as an OpenAI tools array: BossTerm 12,056 bytes, `boss` 39,785, naive merge 51,840 - roughly 13k tokens riding every turn. After tier-1 exclusion and collision-dropping, 99 tools and 37,915 bytes. The ceiling is a knob rather than a decision BossTerm makes for the embedder, and every tool it drops is logged by name. Schemas are byte-capped like descriptions, since a tool *count* does not bound a payload and `properties` is usually the larger half of a tool object (#349)
- The tool source is embedder code behind a hot-swappable classloader, called from inside a live call, and is treated that way: enumeration runs on a pool thread with a deadline and falls back to the last good list, invocation reuses the existing `VoiceToolTimeouts` rung and `clampToolResult`, and the invocation path catches `Throwable` because a hot-reloaded classloader fails with a `LinkageError` rather than an exception. Shares are untouched and keep the curated catalog - this is in-app only (#349)
- Schema value validation deliberately stops at "`type` must be a string": that shape is unambiguous and certainly fatal, whereas BossTerm becoming a JSON Schema validator would mean guessing at an accepted subset that is not documented in that detail - and a validator stricter than OpenAI's silently drops working tools, which is the same harm pointing the other way (#349)
- Every `parentScope.launch` in the MCP manager moves onto a lifecycle-backed scope, so one cancel reaches all of them - including any launch a straggler starts afterwards, which no read-then-cancel of a single reference can do. This supersedes the mutex-guarded `reattachJob` cancel from #331 (#348)
- On the dispose path the engine stop uses a 200ms/800ms budget rather than reconcile's 500ms/1500ms. A long-lived SSE client (Claude Code holds one open continuously) counts as an in-flight call, so Ktor waits out the full grace period every time and that grace is the dominant term. Draining politely is worth 500ms while the app keeps running and only the port is changing; on dispose every client is losing the endpoint anyway, so 200ms is the right semantics rather than merely the faster one. Typical cost is a few ms with no engine and ~200ms with a client attached (#348)
- `ExternalVoiceTool.irreversible` now has a test. It was never actually exercised - deleting it from the policy broke nothing, because every gated tool in the suite was gated by its *name* - yet that flag is the only thing that reaches `rpa_run` and `evolver_evolve`, precisely the case its KDoc claims it exists for (#349)
- The `stop()` drain is deterministically load-bearing in tests. The previous assertion caught a dropped drain only by luck, depending on whether a cancelled `delay()` had finished unwinding by the time it ran; the cancelled fan-out now sleeps explicitly in a `finally`, well inside the drain budget (#348)
- `callLabel` is a plain `String` rather than a provider lambda: context menus need a provider because their content is recomputed per open, but a product name is fixed at embed time, and a String parameter already recomposes if the embedder passes state-backed text. It is not added to `EmbeddableTerminal`, which renders no call affordance at all and would leave the knob wired to nothing. The share viewer's own Call button keeps its fixed name - it is a static web asset, and the server behind it may be the daemon, a separate process with no embedder in it (#347)
