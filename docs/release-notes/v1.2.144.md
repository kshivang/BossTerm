# Release Notes - v1.2.144

**Release Date:** 2026-08-05

## Highlights
BOSS Blueprint arrives as the new default identity, matching bossconsole.ai so the grid inside a tab and the window around it read as one surface. Alongside it, two theme slots that every theme set and nothing ever painted - `searchMatch` and `cursorText` - now have readers: search highlighting follows the active theme, and a block cursor repaints the character it covers instead of hiding it. Boss Calling can also take its OpenAI key from an embedder that already collected one, so BOSS users stop pasting the same key twice.

## New Features
- **BOSS Blueprint**, a terminal palette and chrome token set matching bossconsole.ai, shipped as the product default. It shares the host floor (ink `#05070B` = the site's `--ink`) and takes its cursor from `--blue-bright` rather than `--blue`, because a block cursor has to stay visible against the floor - 4.8:1 versus 3.8:1. Existing installs keep their saved theme; only fresh installs pick this up (#357)
- `BuiltinThemes.PRODUCT_DEFAULT` so callers stop hardcoding the default theme object. Deliberately not named `DEFAULT`: `BuiltinThemes.DEFAULT` is the stark black-on-white XTerm theme, which is a *named* theme and not the product default (#357)
- `docs/design-system.html` gains a themes section with both BOSS palettes side by side and the site sources for each Blueprint value. The page itself still renders in Operator and now says so - its hexes are the reference definition of what each slot is for (#357)
- Boss Calling's OpenAI key can come from an embedder-registered source consulted before `~/.bossterm/voice.json`. In BOSS the key already lives in the secret-manager plugin's Settings → AI Providers, so a user was pasting it twice. `VoiceKeySource` is a plain lambda rather than a typed provider because BossTerm also ships standalone and cannot depend on `boss-plugin-api`; it is process-wide because three unrelated paths read the key - the in-app call, the share server's ephemeral mint, and share advertisement. The file, its chmod-600 storage and the settings UI that writes it are untouched and remain the only source for the standalone app (#361)

## Bug Fixes
- `searchMatch` had no readers at all. The in-buffer highlight read the *scrollbar* marker settings, so `foundPatternColor` - what `applyTheme` writes `theme.searchMatch` into - was never painted, and changing "Search Match" in the theme editor did nothing (#360)
- `cursorText` had no readers either. A block cursor is an opaque `drawRect` on an overlay above the text canvas, so the character under it was simply invisible and no colour could fix that. Block shapes now repaint the covered glyph on top of the cursor. Underline and bar are excluded: they sit at the cell edge, hide nothing, and repainting there would double-draw the glyph the text pass already rendered (#360)
- The cursor's glyph repaint skipped character handling the text pass does, and each omission was a visible artifact. `resolveCursorGlyph` now declines every case the text pass itself declines: the DWC private-use marker (painted as tofu), the double-width lead cell (the one-cell clip would slice it in half), surrogate halves (painted U+FFFD), and blink-off cells (painted steadily). **HIDDEN (SGR 8, conceal) was revealed under the cursor while invisible everywhere else** - password prompts use conceal and the cursor sits exactly on the character just typed, so that was a disclosure rather than a cosmetic bug (#360)
- The repaint indexed the line with a *visual* column while `charAt` and `analyzeCharacter` are *buffer*-indexed. Those coincide only while the line holds no multi-unit grapheme, so one emoji, astral char or Nerd Font glyph earlier in the line shifted everything after it - and the caret resting on an empty cell repainted a phantom duplicate of the previous character. Now converted through `visualColToBufferCol` like every other site that indexes a line from a screen position (#360)
- The blink gate read the wrong clock. `resolveCursorGlyph` was handed `cursorBlinkVisible` (`caretBlinkMs`), but SGR blink runs on `slowBlinkVisible` / `rapidBlinkVisible` - three separate flags on three separate timers. So `caretBlinkMs=0` pinned the flag true and repainted blink-OFF cells, and `enableTextBlinking=false` made a steady cell flash on the caret's clock. Each option is now gated against its own clock (#360)
- The repaint used `sharedFont` at Normal weight, but `renderCharacter` routes emoji, technical symbols and cursive/math to fallback families. Surrogate rejection already covered the astral cases; BMP technical symbols (U+23E9..U+23FF) were being repainted in the wrong font, and are now declined via the same classifier the text pass uses. Bold and italic are carried through rather than flattened (#360)
- The current-match outline was inside the per-cell fill loop, so a multi-cell match got a box around every letter - and because a centred stroke paints each shared boundary twice, the internal dividers read louder than the border they were part of. A six-character match looked like a grid of boxed letters. Now stroked once around the whole span, inset by half the stroke so it does not bleed into neighbouring cells (#360)
- Search highlighting ran after the text pass, painting a translucent wash *on top of* the glyphs it highlighted, so alpha served two masters: emphasis and legibility. It now draws before the text, as selection already did. Measured worst case across all twelve builtins, as a fraction of each theme's own foreground-on-background contrast: the current match's wash over the glyphs was 11.6% of baseline (1.71:1) - the worst-reading state in the terminal - against 34.8% (2.92:1) for a single fill behind untinted glyphs. Every match now gets the same fill and the outline carries the which-match distinction on its own (#362)
- OSC 12 lets an app replace the cursor *fill* without saying anything about the glyph, and `cursorText` is authored against `theme.cursor` - so painting the theme value regardless meant a dark app-set cursor got a dark glyph smeared across it, strictly worse than the blank block it replaced. The glyph colour now falls back to whichever of the theme's own floor/text colours sits further from the effective fill in luminance. Theme-provided cursors keep using `cursorText` (#360)
- The accent was being used as body text in the settings chrome - slider readouts, URLs, "Show Advanced" at 12-13sp - all through a single `signal` mapping. Under Blueprint that is 3.5:1 on `raised`, below the 4.5:1 AA floor. `UiTheme` gains `signalText` and `SettingsTheme` gains `AccentTextColor`; 31 sites were swept over to it, leaving the 7 progress indicators on the fill since those are graphical objects under the 3:1 floor. Derived themes get `legibleAsText`, which walks the accent toward the theme's own text colour until it clears 4.5:1 against ink, panel *and* raised, then past it to the luminance extreme when converging on the foreground alone cannot succeed (#357)
- `applyThemeById` was a third site dropping to the stark black-on-white XTerm theme instead of the product default - and unlike the two already fixed, it is public API on an embeddable library, so a stale id from an embedder took the whole app there. `ThemeManager` had the same bug on deleting the active custom theme, two lines above a comment stating the opposite intent (#357)
- Moving the default was not a one-line edit: `UiTheme.fromTheme()` short-circuited on `theme.id == DEFAULT_THEME_ID` to return the hand-authored Operator chrome (so flipping the constant alone would have silently lost Operator's authored values), `TerminalSettings`' fresh-install colours render until a theme is applied, and `BossUiTheme` seeded its chrome to Operator - which would have flashed amber for any chrome composed before `loadActiveTheme()` landed. All three now go through an id-keyed `EXACT_TOKENS` map (#357)
- Two glyphs in `design-system.html` were flattened to a bare hyphen by the em-dash prose sweep: the titlebar mock's minimize control (now `&minus;`, since a hyphen renders far too short beside the maximize and close glyphs) and five "not applicable" token-mapping cells (now `n/a`) (#358, #359)
- The Maven Central POMs and the `.deb` Maintainer field carried a personal gmail address. The deb maintainer is now `support@risalabs.ai`, matching BossConsole and the published apt metadata; the POM developer contact is `enterprise@risalabs.ai`. Release workflows commit as Risa Labs rather than `github-actions[bot]`, and the README and wiki point at the canonical www URL

## Improvements
- Em-dashes in prose and user-visible string literals become a spaced hyphen, matching BossConsole house style. Code comments are deliberately untouched - they hold most of the em-dashes and no user reads them. Literals were rewritten with a scanner tracking line and block comments, raw strings, escapes and char literals, because a naive quote-pair approach rewrote comments and Kotlin closes a raw string on the *last* three quotes of a run (#358)
- The theme drift guard could not catch drift: asserting the six mappings that exist passes when a seventh slot is added, which is the exact failure mode that let `searchMatch` and `cursorText` die. It now enumerates `Theme`'s String properties and requires each to be mapped, read directly by a renderer, or named on `KNOWN_UNWIRED` (#360)
- The theme-propagation test was a tautology - it hand-built the same `copy(...)` and asserted its own values, so it passed green with the mapping deleted. The mapping is now a real function (`withThemeColors`) that `applyTheme` calls and the test drives (#360)
- Theme rendering is tested on **pixels**, not on plumbing: passing a colour in proves nothing about whether a glyph reaches the canvas, which is precisely how these slots stayed dead while looking wired. Each guard was verified by removing the code it covers and confirming a *named* failure (#360)
- The 4.5:1 glyph floor is now enforced for `cursorText` across all twelve builtins. `solarized-light` (4.13:1) and `one-dark` (4.33:1) are faithful ports of published themes and are recorded as exempt rather than restyled, and the guard fails if that list grows or goes stale (#360)
- A round-trip test pins the builtin background hex strings, which terminal-tab's host-theme bridge compares against `colorToHex(hostInk)` to pick a curated builtin. `colorToHex` truncates, so a value one below would not throw - it would just never match, silently downgrading both BOSS identities to a derived approximation (#357)
- Test count over the release: 907 → 927, 0 failures. The voice-key seam adds 8 cases, mutation-verified twice - inverting the precedence fails two by name, and removing the failure isolation fails the throwing-embedder case (#357, #360, #361, #362)
