# Release Notes - v1.2.145

**Release Date:** 2026-08-07

## Highlights
Scrolling inside an app that owns its own scroll region - a Claude Code session is the common case - could corrupt rows outside that region, leaving characters where they did not belong and getting worse the faster you scrolled. SD/SU and IL/DL now share one containment-checked rotation, so a scroll can no longer reach past a margin.

## Bug Fixes
- Scroll-region rotation escaped its margins and corrupted the buffer, not just the render. An app that pins UI below its region (Claude Code keeps its prompt box and "Jump to bottom" affordance there, driving the transcript with `ESC[2;Nr` plus SD/SU) had that band overwritten mid-line - and never repaints it, because from its own model nothing there changed, so the damage persists (#363)
- `insertLines` (SD, `CSI nT`) resolved its removal index *inside* the removal loop. Each removal shifted the rows above `lastLine` up while `lastLine` stayed put, so the second removal took the row below the margin: rows r1..r10 with region 2..9 and count 3 deleted r9, then the pinned r10, then r8, leaving r7 in row 10. A larger count damaged more rows, which is why a fast flick looked far worse than a slow scroll (#363)
- `deleteLines` (SU, `CSI nS`) bounded its loop by `y < size` rather than by the region, so any count past the region height destroyed the rows below the bottom margin too - and on a top-anchored region pushed them into scrollback. It also derived its blank-insertion index from the requested count instead of the number actually removed, so the blanks landed above the region top (#363)
- The region was measured before it was materialized, letting the *painted* row count define the bottom margin and dropping rows that should have shifted into the unpainted part. Reachable rather than theoretical: `IncrementalSnapshotBuilder` iterates `0 until size`, so a short screen stays short (#363)
- IL/DL (`CSI L` / `CSI M`) ignored the region's TOP margin. With `ESC[2;9r` and the cursor on row 1, `BossTerminal.insertLines` rotated from row 1 and panned a row the region does not own - the same defect class as the bottom margin. DEC VT510 makes IL/DL a no-op with the cursor outside the region; the check lives in `BossTerminal` because only the terminal knows the cursor (#363)
- `insertLines` lost its `count <= 0` guard when it began delegating, so a negative count reversed direction and panned up instead of no-opping. Not reachable from CSI parsing, but `Terminal.insertLines` and `TerminalTextBuffer.insertLines` are both public (#363)

## Improvements
- SD and SU are the same rotation with opposite signs, which is how they came to disagree; they now share one `rotateRegion` that bounds the move to the region height. Direction is a `panDown` flag with a non-negative magnitude rather than a signed delta, which removes `abs`, the zero guard and the sign branch (#363)
- The pan-down path no longer allocates the removed-rows list it discards - that is Claude Code's scroll hot path (#363)
- A behaviour change surfaced by the fix is documented and pinned rather than left implicit: materializing to the bottom margin means a partly painted MAIN screen hands 5 rows to scrollback on a 5-row scroll even when only 3 are painted, because a real 24-row screen has those blanks (#363)
- `ScrollRegionContainmentTest` lands in `bossterm-core-mpp` where the defect lives - containment in both directions, oversized counts, a partly painted screen, IL/DL with the cursor inside and outside the region, and which rows a top-anchored region may put in scrollback. `LinesStorageRotationTest` holds the clamp contract at the storage level, without the emulator in the way (#363)
- `aRegionBelowTheTopAddsNoScrollback` could not fail - `scrollArea` only feeds history when `scrollRegionTop == 1`, and the alternate buffer suppressed history for a second independent reason. It now asserts on the rows, which is the property it was reaching for and a genuine pre-fix failure (#363)
- `CursorRowDriftTest` moved to `bossterm-core-mpp`: it exercises emulator and cursor arithmetic that all lives there and only used `ComposeTerminalDisplay` to satisfy a constructor. The shared `NoopTerminalDisplay` fixture replaces what was about to be a fourth private copy; `TerminalTextBufferBatchTest`'s stub is renamed `RecordingTerminalDisplay`, since a same-named class in the same package compiles but is a trap (#363)
- Regression coverage was mutation-verified against pre-fix code: 9 of 10 containment cases and 5 of 8 storage cases fail with `LinesStorage.kt` and `BossTerminal.kt` reverted to master. Test count over the release: 927 → 1015, 0 failures (#363)
