# Release Notes - v1.2.147

**Release Date:** 2026-08-07

## Highlights
Scrolling back through a session that is still producing output now stays put. The scroll offset is measured from the live bottom of the buffer, so every line appended to history used to drag the text you were reading upward one row at a time; the viewport is now anchored to its content as history grows.

## Bug Fixes
- A scrolled-up viewport no longer drifts as new output arrives. Lines appended to history are counted as they land and folded into the scroll offset on the frame that first shows them, so the content under the viewport holds still while a build or a long command keeps writing
- Output written by a full-screen TUI no longer moves the main-screen viewport. Alternate-screen appends are excluded at the moment they fire, so a main-screen append banked just before a TUI starts survives until the TUI exits instead of collapsing the offset against the alternate screen's (usually empty) history
- Clearing the screen (`CSI 3 J`, what plain `clear` emits) while scrolled up no longer leaves the terminal rendering blank. The viewport returns to the live bottom rather than pointing into a history that no longer exists
- Wheel scrolling on an idle terminal works as before. A cached offset keyed on the redraw trigger could render the view frozen and then write the stale value back over a fresh scroll, since the wheel handler moves the offset without requesting a redraw; the correction is now consumed once per frame and later recompositions read the offset directly
- Appends that arrive mid-frame are no longer lost. The pending count is peeked during composition and subtracted only once the frame has actually been applied, so a discarded composition or a frame rejected by a DEC 2026 synchronized update leaves the count banked for the next one instead of dropping it into permanent drift
- The correction no longer applies to a frame that does not contain the appended lines. When a synchronized update causes the previously retained snapshot to be painted, no fold is produced, removing a shift-and-snap visible when scrolled up while a TUI redraws
- A backgrounded tab keeps compensating. The append counter is now owned by the session alongside the scroll offset and registered for the tab's lifetime, instead of being composition-scoped and dropped on background — a tab that drifted unwatched used to land somewhere else when reselected
- `EmbeddableTerminal.scrollBy` and the command-block scroll actions now go through the same scroll entry point as the rest of the app, so the rule that clears banked appends when the viewport leaves the live bottom is no longer bypassed

## Improvements
- Coverage for the new behaviour: history-append anchoring, the alternate-screen exclusion, the peek/consume split, the clear case, and the height-shrink path that pushes rows into history
- A test settles the question of whether compensating the offset drags selections. It does not — selection anchors are resolved by line identity against the render snapshot each frame, so the anchored row and the offset move together and the on-screen row is unchanged
- Published the v1.2.146 release notes and linked them from the release index

## Breaking Changes
None
