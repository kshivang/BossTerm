# Release Notes - v1.2.148

**Release Date:** 2026-08-08

## Highlights
The caret no longer jitters or loses its blink rhythm while you scroll. Four independent causes on the UI thread — a column read straight from the live emulator, a cursor captured after the text it belongs to, a blink loop that drifted whenever a wake-up was late, and hyperlink detection re-running on every wheel tick — are fixed, and the same pass removes a class of repaints that ran forever on an idle terminal.

## Bug Fixes
- The caret no longer jitters during a scroll gesture. Its column bypassed the render frame entirely and fell back to the live emulator column, so the painted caret paired a fresh column with a row from an older frame and re-read it on every wheel event; the column now travels in the frame with the row it belongs to
- The cursor and the content under it are captured at the same instant. The snapshot released the buffer lock before the cursor was read, and `setCursor` wrote x and y separately — both fields now live in a single atomic snapshot taken under one lock hold
- The blink phase no longer walks. The loop measured its delay from the moment it resumed, so a late wake stretched the period and shifted every edge after it, with the drift tracking scroll activity; edges are now derived from a monotonic epoch and slept to absolutely
- A block caret's glyph stays in sync with blinking text underneath it. The gate ran outside the observed scope, so a text-blink toggle could leave the caret painting a character the text pass had already blinked away, indefinitely on a static screen
- The caret repaints on a theme switch and on an in-window focus change instead of holding the old colour and the old focus alpha until something unrelated recomposed
- Wrapped hyperlinks in scrollback are assembled from the right lines. The scroll offset was added where every caller subtracted it
- Hyperlink targets no longer go stale across a `cd`. The working directory and the file-path-detection setting are part of the detection memo's key, as is a registry revision, so an embedder adding or removing a pattern at runtime reaches rows that were already memoized
- Hover detection over a run ending on the last screen row now hits its memo. The forward walk checked the wrap flag before the bounds and read one row past the end, putting a never-equal placeholder in the key — a miss on every single pointer move, exactly where a live TUI's wrapped output sits

## Improvements
- Wheel scrolling no longer costs two full text renders per event. Detection was reading and writing draw-phase state that re-invalidated the draw node, and its key folded in the scroll offset so every tick re-ran ~14 regexes over every visible row; it now runs one row at a time on hover, memoized on line identity
- An idle terminal is quiet again. A steady-shape caret (DECSCUSR 2/4/6), a hidden caret (`CSI ?25l`, which full-screen TUIs hold for long stretches) and a caret scrolled off-screen each repainted a pixel-identical layer twice a period for the life of the tab; the clocks are now read only when they can change what is painted
- The hover and run walks are capped at 64 rows in each direction, so `cat` of a minified file — one logical line thousands of rows long — no longer walks and compares the whole thing on every pointer move. That still spans ~5k characters at 80 columns
- The UI thread takes one buffer lock per composition instead of two, `setCursor` allocates only on a real change rather than once per output chunk, and the cursor overlay is a skippable composable over one stable holder instead of a lambda capturing a dozen unstable values
- The hyperlink row cache is cleared on resize and on clear-scrollback, releasing the buffer lines it pinned
- Test suite grew from 1069 to 1084, with new coverage for the headline column fix, the draw-time glyph gate, the blink phase loop, cursor-frame equality, the wrapped-run memo in both directions and the walk cap. The tearing test was verified to fail against a reintroduced split write
- Published the v1.2.147 release notes and linked them from the release index

## Breaking Changes
Embedder-facing only, both in `compose-ui`:
- `Hyperlink` row numbers (`row`, `startRow`, `endRow`, `rowSpans` keys) and `JoinedLineInfo.startRow`/`endRow` are now **buffer** rows rather than screen rows — 0 is the top of the live screen and negative indices reach into history. Add `scrollOffset` to convert one to a screen row. They previously changed meaning silently as the viewport scrolled
- `RenderingContext` no longer carries `workingDirectory`, `detectFilePaths` or `hyperlinkRegistry`; hyperlink detection left the draw phase, and `detectForBufferRow` now lives on `HyperlinkDetector`
