# Release Notes - v1.2.149

**Release Date:** 2026-08-08

## Highlights
Right-click menus on macOS are now real OS menus. BossTerm's popups were Swing `JPopupMenu` painted in BOSS theme tokens; they are now `java.awt.PopupMenu`, peered onto a genuine `NSMenu`, which brings system material and metrics, automatic light/dark, native keyboard navigation and accessibility, shortcut glyphs, and correct emoji — with no z-order risk over the Skia canvas.

## New Features
- Native context menus on macOS. Rendering moved behind a `ContextMenuRenderer` seam with two implementations: the native menu on macOS, and the existing themed Swing menu everywhere else. `ContextMenuController` still owns the menu model and the visibility lifecycle
- `TerminalSettings.useNativeContextMenus` turns the native path off and returns you to the themed menu. Embedders can force either value via `TerminalSettingsOverride`, and the setting is read per show rather than frozen at session creation
- Linux and Windows always get the themed Swing menu. Only macOS was measured; on Linux the AWT peer is the Motif-era XAWT menu that ignores GTK, and on Windows the peer plausibly blocks the EDT for as long as the menu is open and does not follow system dark mode. Widening the gate is one predicate in `shouldUseNativeMenus` plus a measurement on that platform

## Bug Fixes
- The Swing menu path never set `isLightWeightPopupEnabled = false`. It only worked because BossConsole makes a global call that a library cannot assume and standalone BossTerm does not make at all — a lightweight popup paints behind the accelerated surface
- The #126 focus-restoration effect never fired: it watched a flag that only a never-taken fallback ever set. It now arms when a menu actually opens, records whether the terminal held focus at that moment, and restores only on that edge — so opening **Find...** or **Show Debug Panel** from the menu no longer has focus yanked back to the terminal 50ms later
- Invoker resolution no longer picks the largest window. `getWindows()` is not in z-order and includes heavyweight popup windows, so it now filters to frames and dialogs and prefers active-then-smallest, with a fallback for edge clicks (`Rectangle.contains` is half-open on the right and bottom edges, which could otherwise leave no candidate and show no menu at all)
- `PopupMenu` instances no longer accumulate on the invoker. Detach previously happened only on the same renderer's next `show()`, so every tab closed after a right-click stranded a menu on the long-lived `ComposeWindow`, retaining its items, listeners and captured closures
- **Select All** no longer advertises Ctrl+A on Windows. It is bound meta-only on purpose so Ctrl+A passes through to the terminal (tmux prefix, readline beginning-of-line)
- The visible flag no longer sticks true. Dismissing by switching applications produces no input event, and a watcher that failed to install reported nothing at all — both pinned `menuVisible`, which TabBar feeds into its hover reveal
- Menu teardown is scoped to the menu that installed it, so an item action that opens another menu on the same controller does not tear down its own successor
- Ampersands are escaped in native labels on Windows, where `AppendMenu` treats `&` as a mnemonic prefix — reachable through git branch names and account emails
- A menu item rejects a shortcut that is not a virtual-key constant; `MenuShortcut` takes a VK code, and a lowercase `'c'` would have rendered as something arbitrary
- `resolveInvoker` no longer calls `toFront()`/`requestFocus()`, which let a right-click raise a BossTerm window over the host app when embedded

## Improvements
- Three `java.awt.PopupMenu` behaviours were measured rather than assumed, and each shapes the code: `show()` does not block, so its return is not a dismissal signal; nothing cancels an open menu, so item actions are fenced on a generation counter and go inert once the controller moves on; and there is no dismissal event on any AWT mask, but an open menu holds the input grab, so the flag clears on the next input event without being able to clear early. Ctrl+click was verified not to be a false positive — pressing and releasing Ctrl across an open menu delivers zero AWT events
- `hide()` greys an orphaned menu's items, including submenu children, before letting go of it. The generation fence already made them inert, but "clicks and nothing happens" reads as a hang
- `addAWTEventListener` and Toolkit acquisition are guarded — they need `AWTPermission`, and a strict embedder host would otherwise take the right-click down with them. The watcher reads only the event id and is cleared on item selection
- Menu mapping is split into a toolkit-independent `planNativeMenu()` step so it can be tested headlessly; constructing any `java.awt.MenuComponent` throws `HeadlessException`. A labelled separator degrades to a separator plus a disabled item, which is how macOS renders section headers anyway, and item icons are dropped since `java.awt.MenuItem` has no icon API
- Removed the dead `MenuState`/`executeItem` state and the no-op `ContextMenuPopup` composable
- 37 tests for the new path, covering the dismissal predicate, override precedence through an injected platform, anchor arithmetic, the shortcut contract, invoker ordering and the edge-click fallback, the re-entrancy path, and the no-invoker and unreadable-settings fallbacks
- Documented the setting in `Configuration.md` and `API-Reference.md`, the override in `embedding.md`, and the platform gate plus the measured macOS facts in `AGENTS.md`
- Published the v1.2.148 release notes and linked them from the release index
