# Release Notes - v1.2.150

**Release Date:** 2026-08-19

## Highlights
The macOS window now runs its background under a unified native title bar, with a title that tracks the live session instead of the name it launched with. Two long-standing correctness bugs go with it: commands written programmatically now submit with CR rather than LF — which is why they silently failed to run on Windows ConPTY — and text a CLI hardcodes as white is no longer invisible on a light theme.

## New Features
- **Unified native title bar on macOS.** `fullWindowContent` + `transparentTitleBar` let the app background run under the strip so the traffic lights sit on it, with content inset by the strip height. The inset applies in fullscreen only, never when zoomed — macOS zoom keeps its title bar, so a zoomed window still needs the inset. `WindowState.placement` is trusted for that distinction after tracing it to skiko's `osxIsFullscreenNative`; a bounds-vs-screen heuristic was tried and removed, because it cannot tell fullscreen from zoom once the menu bar and Dock auto-hide
- **A window title that tracks the session.** It resolves a **Rename…** custom title, then OSC 2, then the tab's own title. Completion notifications resolve the same way, so an unfocused tab says which session finished
- `lightBackgroundMinContrast` (default 4.5, `1.0` = off) sets the minimum contrast enforced for foreground text on a light background

## Bug Fixes
- **Commands submitted with LF did not run on Windows.** Every programmatic write to a PTY ended its command with a bare LF. On a Unix pty that works only because the line discipline's `ICRNL` maps CR to NL on input, which is why it went unnoticed for years. ConPTY does no such translation: a bare LF is Ctrl+J, so PSReadLine inserts a newline into its edit buffer and the command sits unrun at a `>>` continuation prompt. Measured against Windows PowerShell 5.1 over ConPTY by writing each form to a real pane and reading the scrollback back — `\r` is the only correct form. CRLF is the trap worth naming: it looks correct because the command works, and the damage lands on the user's *following* keystrokes
- Every submit path now routes through the new `util/TerminalSubmit.kt`: the AI-assistant launch line (context menu, AI menu, and the share viewer's LaunchAI), the `initialCommand` path behind MCP `run_in_panel` and tab restore, MCP `run_command`, the command-block re-run, and the ~20 git/gh/shell-config menu items. The fix lands at the ~100 literals as well as at the writers, so a command is correct regardless of which writer it is handed to — right-click ▸ Git ▸ Status previously stranded at a `>>` prompt on Windows while the identical item on the Tools menu worked
- `run_in_panel` now trims CR as well as LF from the caller's script, which previously left the CR of a CRLF-terminated script behind and submitted twice
- The public embedder API is fixed too. `state.write("cmd\n")` is the documented snippet in AGENTS.md and in both example apps, and it routed to `writeUserInput` verbatim — so an embedder following the docs got exactly the reported bug. `write()` now normalizes newlines to CR
- The voice agent was being instructed to end every `send_input` with `\r\n`, with a test asserting it on the reasoning that CRLF is what a terminal sends for Enter. It isn't, and the prompt after every command the agent ran was left in continuation mode. Now `\r`
- **Hardcoded white text was invisible on a light theme.** A CLI that assumes a dark terminal — Claude Code emits a literal `ESC[38;2;255;255;255m` — painted text at 1.07:1 against the paper floor. A 24-bit color bypasses the theme and palette layers entirely, so the correction happens per cell at paint time: `ColorUtils.legibleOnLightBackground` mirrors a failing glyph's HSL lightness, preserving hue and saturation, then clamps toward black for whatever the mirror cannot fix. White becomes near-black so primary text reads as ink, `#999999` stays a grey, a brand orange stays orange, and a fully saturated color — which sits near lightness 0.5 and so barely moves under the mirror — is rescued by the clamp
- The share viewer had the same bug and could not reuse the guard: it renders through xterm.js, which has no per-cell foreground hook, and its live text is a raw pty stream, so nothing host-side can rewrite the color. The host now sends xterm.js's own `minimumContrastRatio` as a floor instead, validated viewer-side because it crosses the wire

## Improvements
- The contrast guard is scoped to light backgrounds on the WCAG 0.1791 pivot, so every dark theme renders byte-identically and a cell carrying its own dark background keeps its white text. It measures against the background pass 1 actually painted, so `INVERSE` cells are corrected against the right floor, and it applies after DIM, which keeps `ESC[2m` reading as secondary without changing `applyDimColor`
- The OSC 1 / OSC 2 split is preserved deliberately — OSC 1 names the tab, OSC 2 names the window, and oh-my-zsh emits both — and the OSC 2 slot is cleared at prompt start, so a program stops naming the window once it exits
- The window appearance is now derived from the terminal background and applied before AWT boots. `transparentTitleBar` puts the title text over our own background while AppKit still picks that text's colour from the window appearance, so following the system made the title unreadable whenever the two disagreed (confirmed on a light desktop with the default dark background)
- MCP `send_input` stays byte-verbatim on purpose: a bare LF is a keystroke a caller may genuinely want — a newline inside a multi-line prompt to an AI CLI — and rewriting it would remove the only way to send one. Its description, and the daemon's, now spell out `\r` vs `\n` instead
- `pasteText` now calls `normalizeSubmitNewlines` instead of open-coding the same two replaces, making the helper's claim to match `pasteText` true by construction
- Workflow auto-run is deliberately *not* normalized when `workflowsAutoRun` is unset — the rendered text is left at the prompt to edit, so it keeps its LFs
- Window transparency is deliberately not part of the title-bar work: AWT gives an alpha-capable backing store only to windows it treats as translucent and refuses that for decorated frames. Measured and recorded in AGENTS.md so it is not rediscovered
