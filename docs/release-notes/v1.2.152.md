# Release Notes - v1.2.152

**Release Date:** 2026-08-22

## Highlights
A follow-up release to the light themes in v1.2.151: the chrome stops using the disabled colour tier for real text, and the selected row in the command palette and history overlay gets its indicator back. Alongside that, a tab closing mid-launch no longer lets a shell spawn escape as an unhandled error.

## Bug Fixes
- **The chrome used the disabled tier for readable text.** The `muted` token is 2.37:1 and 2.48:1 against `panel` on the two light identities — under the 4.5:1 text floor and under the 3:1 component floor — yet 15 genuine 10–11 sp labels and icon tints were pointed at it: remote-group section labels, three placeholders, the command-palette group column, and the update banner's body and TextButton labels. Those sites now take `mist` (4.64:1 / 5.45:1). `muted` itself is unchanged and keeps the uses that really are disabled or decorative — the OFF status dots, the scrollbar block-marker fallback, and SearchBar's nav arrows with no matches
- **The selected command-palette and history row had a fill and no indicator.** `signalWash` alone marked which row Enter would run, and against the panel it sits on that is 1.10:1 on daylight, 1.20:1 on blueprint-light and 1.07:1 on operator — below the 1.25 floor the light-theme guard already asserts for a terminal selection. Both rows now carry the 2.dp indicator the theme's own rule requires, which also repairs a small regression on the dark themes (1.47:1 there)
- **A shell could be started for a session that was already gone.** Disposing a tab cancels its scope, but `PtyProcessBuilder.start()` is a blocking JNI chain with no suspension point, so a coroutine already inside it never notices; session init does real work first, and that whole span is when a tab can be disposed. Seen live when a plugin reload sent a pty spawn at its own closed classloader. There is now a cancellation check before the call, and the spawn catches `Throwable` rather than `Exception` — a closed classloader raises `NoClassDefFoundError` / `ExceptionInInitializerError`, which are Errors, so the documented "returns null on failure" contract broke in exactly the case that produced the crash. Cancellation is rethrown rather than reported as "Failed to spawn process" on a tab already on its way out

## Improvements
- **Two new guards, for holes nothing existing could catch** — a literal scan cannot see a token used in the wrong *role*, and `UiTheme` was unguarded entirely. `UiThemeContrastTest` mirrors `LightThemeContrastTest` for the chrome tokens (text at 4.5:1 on all three surfaces, fills at 3:1, onSignal on signal, a perceptible step between ladder rungs), with an inverted assertion pinning `muted` as deliberately sub-floor. `ChromeTokenCoverageTest` gains a scan for `muted` in a `color =` / `contentColor =` position across the 13 converted files; `tint =` is excluded on purpose, since a disabled icon is what the token is for. Both verified by mutation, and both scoped to the two BOSS light identities — one assertion records the themes that would fail a wider sweep so the scope can widen when that debt is paid
- The pty start is injectable now, because a `LinkageError` cannot be provoked through the real `PtyProcessBuilder` — without a seam the Throwable-vs-Exception distinction is untestable, which is how the catch clause came to be Exception-only
- The tab bar collects `raised` once for the whole bar and passes it to each chip, instead of every chip subscribing on its own — and two comments that had drifted from the code beneath them now describe what it actually does

## Breaking Changes
None
