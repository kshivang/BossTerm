# Release Notes - v1.2.154

**Release Date:** 2026-08-24

## Highlights
Hovering a tab chip now opens a themed details card with everything the chip had to clip — the full title, the untruncated working directory, the git branch, the remote a mirrored chip belongs to — plus an optional six-row preview of that pane's screen.

## New Features
- **Tab hover card.** A chip cannot fit much, and what it drops is exactly what you go looking for: which of two same-named tabs is which, and what a background tab is actually doing. Hover now opens a small themed card carrying the full title, the untruncated cwd (the chip's second line is elided to `~/.../Boss/BossTerm`), the git branch, the host label for a mirrored pane, and a non-connected session's state
- **Screen preview.** Under a rule, the card shows the last six non-blank rows of that pane's screen. It reads `TerminalTextBuffer.getScreenLines()` from inside the popup, so the buffer lock is taken on hover and nowhere else, and the result is remembered per pane so a live `tail -f` cannot reflow the card under the pointer. The visible screen, not the history — its bottom rows are the recent output, while the history-inclusive `createSnapshot` that `read_scrollback` uses deep-copies the whole scrollback
- **New `tabHoverPreview` setting** (on by default, Behavior ▸ Tab Bar) gates just the preview section: it draws a *background* pane's output into a popup, which during a screen share is content that was not on screen a moment ago. Title, path and branch stay unconditional
- The collapsed rail's title-only tooltip now renders the same card — dots have no other label

## Bug Fixes
- **A mirrored pane's cwd no longer folds against the local home.** `tildePath(path, home)` takes `home` as a parameter rather than reading `user.home`, because a mirrored pane's cwd belongs to the remote host: folding turned a same-named remote user's `/home/alice/proj` into `~/proj`, right next to "via mac-mini". Remote panes pass null. The `/Users/alice-backup` boundary that must not become `~-backup` is covered by test
- **Tooltips are suppressed while a sidebar drag is in flight.** Reordering slides chips under a held pointer, so each newly entered chip started a fresh dwell that a slow drag outlasts
- The card is suppressed while a chip is being renamed
- The screen read catches `IndexOutOfBoundsException` specifically — index churn against a concurrent resize — and logs at debug rather than swallowing every throwable, since a permanently preview-less tooltip would otherwise be the only symptom

## Improvements
- Placement is `CursorPoint`, matching the MCP pill: only the cursor provider flips and clamps against the window, and a full path on the last chip of a narrow window is exactly where a `ComponentRect`-anchored card gets clipped off the edge
- One shared `chip` lambda feeds the top bar, the expanded left sidebar and the remote group boxes, so all three gain the card at once
- The mirror is resolved once per pane and fed to both the accent and the host label, replacing two O(sessions) `ownsMirror` scans per chip per recomposition. The host label's URI parse — its only expensive branch — is memoised by link, and `hostLabelFor` no longer scans at all for local panes
- Preview rows arrive padded to the terminal width, so blanks are dropped (an idle shell would otherwise preview six empty rows) and each row is clipped at 96 chars before layout rather than laid out at 200+ columns to then ellipsise
- The two line builders are pure and tested (12 cases), alongside new coverage for the preview and for `tildePath`

## Breaking Changes
None
