# Release Notes - v1.2.155

**Release Date:** 2026-08-27

## Highlights
Typing feels immediate: interactive echo drops from 16.4 ms to ~2.0 ms (87%) and bulk output's queue wait falls ~5x, both measured end to end with a new glass-to-pixel latency probe. MCP's `run_in_panel` now reuses its pane instead of carving the tab into a new split on every call.

## New Features
- **`run_in_panel` reuses its pane.** Six calls used to leave six panes and a tab too narrow to read anything in. A split-mode call now runs the script in the tab's existing scratch pane when one is alive — the same per-tab pane `run_command` has always reused, guarded by the same per-pane mutex so two overlapping calls cannot interleave in the shell's stdin. `force_new` restores the old behaviour, and keeps the anchor stacking so opting out still lays panes out in a strip rather than carving up whatever happens to be focused
- **`run_in_panel` returns `reused`,** so a caller can tell "your panel is the one already on screen" from "a new one appeared" without diffing `list_panes`
- **A latency probe you can turn on.** `BOSSTERM_FRAME_PROBE=1` writes `~/.bossterm/frame-probe.json` once a second with `byteToPaintMs` (PTY arrival to the paint that first draws the byte), `triggerToPaintMs`, `queueWaitMs`, `paintCostMs`, `lockedCaptureMs` and `drawCallsPerFrame`. Inert unless set — no timestamps taken and no allocation on any hot path. `benchmark_results/LATENCY_BASELINE_2026-08-27.md` records the measured baseline; `benchmark/latency/README.md` documents the method

## Bug Fixes
- **The debug collector no longer deep-copies the whole buffer 10x/sec when nobody is watching.** Profiling a 5 MB `cat` put 59% of execution samples in `DebugDataCollector`: a 100 ms timer called `createSnapshot()` — every line of screen *and* history cloned — for the life of every tab, and threw the result away, because the panel was closed. Its own `enabled` flag defaulted true with no callers to turn it off. Capture is now gated on the tab's debug panel actually being open (or collection being enabled in settings); the loop keeps ticking so Cmd/Ctrl+Shift+D shows data immediately
- **Ring-buffer trimming is no longer O(n) per chunk.** Both debug buffers trimmed with `while (queue.size > max)`, and `ConcurrentLinkedQueue.size()` walks the list — up to 1000 node traversals per chunk, on the PTY reader thread, for every chunk that crossed the tty. Now trimmed against a tracked counter
- **One exception per character is gone from the parse loop.** The drain loop's liveness check bottomed out in `UnixPtyProcess.exitValue()`, which throws `IllegalThreadStateException` whenever the child is alive — the normal case. A 5 MB `cat` built ~5.5 million exceptions with filled-in stack traces. `isAlive()` now caches for 20 ms and latches death; the loop's real termination signal was always EOF from the data stream
- **Cmd/Ctrl+Shift+D no longer opens a permanently empty debug panel** — the new capture gate read the background-collection flag rather than the panel-visibility flag. The predicate is now a pure, tested function

## Improvements
- **Interactive echo: 16.4 ms → ~2.0 ms.** The 8 ms redraw debounce and the 5 ms `balanced` poll were the entire gap. The debounce is removed and `performanceMode` now defaults to `latency`. Frame counts stay vsync-capped (~62/sec) without the debounce — the frame clock was always what kept the terminal from over-rendering, not the sleep
- **`performanceMode` default is now `latency` (was `balanced`).** A `settings.json` that already pins `balanced` keeps the old 5 ms poll; clear the key or set `latency` to pick up the full improvement
- **Bulk output queue wait ~5x lower** (p50 786–1179 ms → 147–262 ms, p95 1572–1966 ms → 262–360 ms, three runs). Three costs, none visible from reading the code: the per-character exception above; an AWT event per redraw request (`invokeLater` + `InvocationEvent` + a native stack walk, on every buffer mutation — a pending flag now skips the send when one is already queued); and ICU grapheme segmentation running `RuleBasedBreakIterator` over text that was ASCII end to end
- **`visualColToBufferCol` skips the column walk on lines that need no visual mapping.** Every wrap walked column 0 to the full terminal width with an O(runs) `charAt` inside; a line holding nothing above U+007F makes buffer column and terminal cell the same number. ~10% of emulator-thread time, and the renderer's hit-testing benefits too
- **Fewer draw calls per frame.** Blanks now extend a batched text run instead of flushing it (aligned output, indented source and powerline prompts cost one `drawText` per *word* before), and ASCII neighbourhoods skip the ZWJ / skin-tone / regional-indicator probes that can only fire on non-ASCII. `drawText` calls 208 → 30 per frame on a TUI workload and 176 → 60 on scroll, with paint cost 11.26 → 10.24 ms and 5.63 → 2.30 ms. Verified by rendering a committed Unicode-torture fixture with the fast path off and on and diffing the captures — ZWJ families, flags, skin tones, variation selectors, CJK, powerline glyphs, underlines spanning gaps and column alignment are identical apart from subpixel antialiasing
- **The adaptive redraw machinery is gone with the wait it existed for:** `RedrawMode`, `RedrawPriority`, the redraws/sec detector, the mode-transition job, and the 100 ms mode-reset coroutine that every keystroke launched. Net −131 lines
- Correctness guards carry tests that fail when the guard is deleted: the ASCII fast path never skips a probe that would have fired, the blank trim never drops an interior character, the DWC guard snaps back to a wide glyph's start, and the ASCII grapheme path is proved equivalent to the ICU one over every printable ASCII character
- Known, not addressed here: bulk output is improved, not solved — a 5 MB `cat` still arrives as thousands of small PTY reads into an emulator that pulls them back one `Char` at a time. `TerminalLine.merge` (~12% of non-parked emulator thread time) needs run coalescing across splice boundaries before the rope-style fix is safe; `TerminalLineWriteModelTest` ships as the harness for it
